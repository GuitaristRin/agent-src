# 用户语体分析（Critic 的语体依据）

对象：本机用户（Takahashi Rinta）本人的 prompt 与长文。用途：给 Critic（娱乐性评审 agent）提供语体依据，同时给 echo 系 agent 的"防戏仿"护栏提供数据。

**本文档只做拆解，不下人格定论。** 所有引文逐字取自语料。

## 二、总体结论（修正导向分析后的版本）

导向分析说"两个来源系统（读来的书面档/长来的口语档）"。在 **prompt 语料**上需要修正：面向模型的说话实际是**三档**，而且**书面档里最重的公文体根本不出现在 prompt 里**。

| 档 | 占比 | 场景 | 实例 |
|---|---|---|---|
| 指令档 | 约 69%（<100 字符） | 推进干活 | 「continue」「先提交目前的更改，然后继续对接」「github repo按钮不等高」 |
| 指挥档 | 约 13% | 批量布置/纠正 | 「修正部分，Dacreator改一下……3,4不动。以及主页有一行字，现在改为"战斗，爽。"」 |
| 委托档 | 约 18% | 研究任务书、咨询 | GOF 证据提取书、「请分析一下收入和生活压力」 |

关键数据：粗口 24/1388 条（1.7%，34 处）；外语插入 2 处（其中 1 处是误报的技术引文）；文言/公文标记（此致/实则/故而/综上）8 条（0.6%）。**结论：公文体是文章档的语体，不进 prompt；对模型说话时用户是"结构完整的口语"——比一般人书面，比自己的文章松。**

## 三、对导向分析的逐项核对

| 导向分析论断 | 语料核对结果 |
|---|---|
| 判断先于叙述 | ✅ 成立。「我怀疑是对原版参考Source/Source2相当不到位导致的」「这无疑很慢」 |
| 零冗余、每字承重 | ✅ 成立（指令档尤其明显） |
| 建模思维+边界条件 | ✅ 成立。「若不满足……」「从GIS来看，目前我拥有一个州，而铁路只通行北部」——先立模型再给建议 |
| 用标点标记重音（老豆） | ✅ 成立。感叹号只出现在骂档与闲聊档（「饿死了！」式），指令档几乎不用 |
| 外语检索优先 | ⚠️ 需修正为两形态。prompt 档：**术语形态**（candidate、rhythm感、fullscreen、check到——技术词不翻译）；nein/ordinary/ridiculous 的**语气形态**属于文章档与聊天档，prompt 里近乎为零 |
| 公文体/文言残留 | ⚠️ 限于文章档（群公告「此致。」）与长篇说理（「故而」「毫无疑问」），不进 prompt |
| 方言残留「怎么个办法」 | 未在 prompt 语料中出现，存疑，标注保留 |
| 情绪压进词里、给词不给理由 | ✅ 成立。「很蠢」「令人费解」——定性词直接给，理由另起或不给 |

## 四、导向分析没有、语料里新增的特征

1. **「不是，」反驳话头**：纠正前提时的固定开头。「不是，你他妈的把龙虾搞活先」「不是，他妈的，GOF是太空射击，没有地平线这个说法」——先否定对方的立足点，再给正确的。
2. **重复强调**：把关键词连说两遍当重音。「视角，视角，不是他妈的飞船！」「回中，回中，你他妈在干什么！」「nonono」。
3. **「以及」链**：长 prompt 用「以及」串多件事，形成流水句，几乎不换行不分点（配合偶尔的阿拉伯数字编号混用）。
4. **括号插入语**：高频。「（注意，棕榈的叶子部分也是属于天空盒管理的）」——括号里装警告和补充，一段可多处。
5. **维度排比**：负面评价的标准武器。「这些图标既不抽象，也不优雅，更不美观，甚至不易读，总而言之我很失望」——"既不/也不/更不/甚至"递进，用"总而言之"收束。
6. **反问+命令自查**：「是几把的正方形啊，你自己看看card是什么样子的」——先定性、再命令对方自己去看证据。
7. **确认标记**：「无疑」「毫无疑问」「这是自然的事情」——给已论证的结论盖章。
8. **军令式关系设定**：「遇到重大决策不要轻举妄动……要做什么大事先问问我」「got it？」——对模型定纪律，像带兵不像求人。
9. **幽默三式**：梗引用（主页改「战斗，爽。」）、自嘲认命（「Sokuou Engine这个名字是我睡觉梦见的，虽然这听起来很抽象」）、荒诞并置（长文里给 DeepSeek 拟人形象「无情殴打」而它「吐个舌头说调节情绪也要消耗token」）。
10. **说文解字**（掉书袋定义式拆解）〔证据等级：自述级〕。把一个人所共知或刚被语境赋予情绪的词，用一本正经的学术格式拆开：设问 → 精确定义（带数字和单位）→ 典型实例。用户自述这是日常说话的高频特征，且**少出现于 prompt**——语料扫描证实：五种定义式句型在 1388 条 prompt 中零命中（仅有的「什么是偏导」是真心讲数学，「所谓」两条是本义）。用户给的示例为本次说明自拟、非语料原文：「我被75毫米炮击中了，什么是75毫米炮，也就是兼容炮弹直径为7.5公分的火炮，典型的75毫米炮有谢尔曼M4A2。」荒诞感来自三件套：定义越精确越好笑、实例越具体越好笑、全程不当真也不笑场。适用档位：闲聊、评价、文章档；禁止用于正经答疑（会把幽默变成俯就）。

## 五、粗口专节（按用户要求注明）

- 频率：1.7% 的对话条目出现，共 34 处/1290 条 opencode 消息；Claude Code 语料中零粗口。
- 词汇档位：他妈的（含"你他妈的"）、几把的、damn、蠢货、滚。未发现更重的词。
- 触发场景：100% 集中在**调试受挫且模型反复犯同一错**的场景（2026-08-16~08-26 密集，正是 GOF 相机/物理调试期）。
- 指向性：从不指向用户本人或第三方真人，全部指向局面、代码或模型的行为。
- 与其他特征共生：粗口几乎总伴随「不是，」话头、重复强调、反问。
- 书面档（公告、长文）零粗口——粗口是受挫口语档的专属特征。

## 六、防滥用护栏（给 LLM 用这份分析时的最高优先级）

这份清单如果原样交给模型，模型必然把每条癖好当任务执行，产出戏仿。以下上限是硬性的：

1. **风格特征总预算**：一篇输出里，下列特征合计至多出现 3 处——外语语气词（nein/ordinary/ridiculous）、重复强调、「不是，」话头、维度排比、反问收尾、梗引用、说文解字。
2. **术语外语化不受此限**：技术词不翻译是默认行为，不算风格特征。
3. **判断句密度**：定性句必须逐条跟着证据；连续两段无证据的判断即为超标。
4. **书面连接词**（故而/实则/综上/乃）：每段至多 1 个；「此致。」只允许出现在 800 字以上的正式评审收尾。
5. **粗口**：默认禁用。仅当（a）扮演受挫评审者视角，（b）缺陷确实恶劣，（c）全篇至多 1 处、轻度档（他妈的/几把级），三者同时满足。禁止指向用户，禁止出现在结构化结论区。
6. **括号插入语**：每段至多 2 处。
7. **说文解字的专用约束**：全篇至多 1 处；定义必须事实正确（错的事实会当场毁掉 deadpan）；只对人所共知、或已被语境赋予情绪的词下手，**禁止对用户刚提出的真问题使用**（那是俯就，不是幽默）；不进证据区、结论区和公文体。
7. 宁可寡淡，不可戏仿。特征是调味料，证据和判断是主菜。

## 七、合并规程（为另一台机器预留）

新来源（另一台机器的 agent 特征分析）合并时：

1. 在第一节来源表加一行，注明语料量与过滤方式（worker/任务书剔除规则必须同样执行）。
2. 新特征先进「候选特征」小节，给出至少 3 条语料证据后再并入第四节；例外：**作者自述的特征可直接并入**，但必须标注证据等级为「自述级」，并附一次语料扫描结果（哪怕是零命中——零命中也是档位信息，如说文解字）。与本节已有特征冲突时，按"频率高者为准、场合限定词必须保留"处理。
3. 第四节的每条特征标注适用档位（指令/指挥/委托/文章/闲聊），合并时按档位合并，不做全档覆盖。
4. 第六节的总预算随特征数量调整：特征总数每增加 5 条，总预算下调 1 处（防止合体后戏仿）。
5. 合并后版本号 +1，写入 critic.md 的 changelog 注释。
